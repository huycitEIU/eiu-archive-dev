# ADR 002

# Using Node.js for Backend Development

- Status: Accepted
- Date: 2026-07-30

## Context

The project is a document storage and sharing system that allows users to upload, organize, share, and manage documents securely.

The backend is responsible for:

- User authentication and authorization
- Document and folder management
- File upload and download
- Access control for shared documents
- Metadata management
- Communication with Cloudflare R2 object storage
- Providing RESTful APIs for the frontend

The selected backend technology should:

- Handle many concurrent requests efficiently.
- Integrate easily with Cloudflare R2 and relational databases.
- Support scalable API development.
- Be easy to maintain and extend with new features.
- Provide a rich ecosystem for authentication, validation, logging, and file handling.

The alternatives considered were:

- Node.js
- Java Spring Boot
- ASP.NET Core
- Go

## Decision

We will use **Node.js** as the backend runtime for the document storage and sharing system.

The decision is based on the following reasons:

- Its non-blocking, event-driven architecture is well suited for file upload/download operations and other I/O-intensive tasks.
- It integrates easily with Cloudflare R2 through S3-compatible SDKs.
- It provides a large ecosystem of packages for authentication, file processing, validation, logging, and security.
- JavaScript/TypeScript can be used across both frontend and backend, reducing development complexity.
- It enables rapid development and simplifies future feature additions.

## Consequences

### Positive

- Efficient handling of concurrent file upload and download requests.
- Faster development using a unified JavaScript/TypeScript stack.
- Easy integration with Cloudflare R2, databases, and third-party services.
- Large community support and extensive documentation.
- Scalable architecture suitable for future system growth.

### Negative

- CPU-intensive operations (e.g., document conversion or virus scanning) may require separate worker services.
- Poorly managed asynchronous code can reduce maintainability.
- Dependency management requires regular updates to address security vulnerabilities.

### Risks

- Blocking operations can impact overall application performance if not handled properly.
- Heavy document processing workloads may need background job processing or microservices.
- Frequent updates in the Node.js ecosystem require continuous maintenance.
