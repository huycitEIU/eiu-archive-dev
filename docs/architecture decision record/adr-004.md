# ADR 004

# Using Prisma ORM for Database Access

- Status: Accepted
- Date: 2026-07-30

## Context

The document storage and sharing system requires a reliable and maintainable way to interact with the relational database. The backend performs frequent CRUD operations for users, documents, folders, permissions, and sharing records.

The selected data access solution should:

- Provide type-safe database queries.
- Simplify CRUD operations.
- Support schema migration.
- Reduce boilerplate SQL code.
- Integrate well with Node.js and MySQL.
- Improve developer productivity.

The alternatives considered were:

- Prisma ORM
- Sequelize
- TypeORM
- Raw SQL

## Decision

We will use **Prisma ORM** as the primary data access layer.

Prisma provides:

- Type-safe database queries.
- Declarative schema definition.
- Automatic migration management.
- Excellent integration with Node.js.
- Simplified database access through Prisma Client.
- Good maintainability and readability.

Repositories will use Prisma Client to communicate with the MySQL database.

## Consequences

### Positive

- Less boilerplate code.
- Improved code readability.
- Type-safe database operations.
- Easier schema evolution through migrations.
- Faster backend development.

### Negative

- Developers must learn Prisma's schema language and migration workflow.
- Some complex SQL queries may require raw SQL.

### Risks

- Prisma-specific implementation may make migration to another ORM more time-consuming.
- Incorrect migration management may lead to schema inconsistencies.
