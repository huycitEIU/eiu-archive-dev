# ADR 005

# Using MySQL as the Relational Database

- Status: Accepted
- Date: 2026-07-30

## Context

The system stores structured data including:

- User accounts
- Documents
- Folders
- Sharing permissions
- Access metadata

The database should provide:

- ACID transactions.
- High reliability.
- Relational data modeling.
- Good performance for CRUD operations.
- Wide community support.
- Compatibility with Prisma ORM.

The alternatives considered were:

- MySQL
- PostgreSQL
- MariaDB
- MongoDB

## Decision

We will use **MySQL** as the primary relational database.

The decision is based on the following reasons:

- Mature and stable relational database system.
- Excellent compatibility with Prisma ORM.
- Strong support for transactions and referential integrity.
- Well suited for structured data with relationships.
- Easy deployment and administration.
- Large community and extensive documentation.

Binary files such as uploaded documents are **not stored in MySQL**. Instead, they are stored in **Cloudflare R2**, while MySQL stores only metadata such as filenames, storage paths, ownership, permissions, and timestamps.

## Consequences

### Positive

- Reliable transactional data storage.
- Efficient management of relational data.
- Strong consistency through foreign key constraints.
- Mature ecosystem and tooling.
- Easy integration with Prisma.

### Negative

- Not suitable for storing large binary files.
- Horizontal scaling is more complex than some NoSQL databases.

### Risks

- Poor schema design may affect performance as the dataset grows.
- Database backups and migration strategies must be maintained regularly.
