# ADR 006

# Using Ant Design for Frontend UI

- Status: Accepted
- Date: 2026-07-30

## Context

The document storage and sharing system requires a modern, responsive, and consistent user interface for managing documents, folders, user accounts, and sharing permissions.

The frontend should:

- Provide a professional and intuitive user experience.
- Maintain a consistent design across all pages.
- Support responsive layouts.
- Offer reusable UI components.
- Accelerate frontend development.
- Integrate seamlessly with React.

The alternatives considered were:

- Ant Design
- Material UI (MUI)
- Bootstrap
- Chakra UI
- Tailwind CSS with custom components

## Decision

We will use **Ant Design (AntD)** as the primary UI component library for the frontend.

The decision is based on the following reasons:

- Provides a comprehensive collection of production-ready React components.
- Offers a consistent design system for enterprise web applications.
- Includes built-in support for common components such as tables, forms, modals, notifications, menus, and file upload.
- Reduces development time by minimizing the need to build custom UI components.
- Integrates well with React and modern frontend development practices.
- Supports responsive layouts and accessibility features.

## Consequences

### Positive

- Consistent look and feel across the application.
- Faster frontend development using reusable components.
- Reduced maintenance effort for UI implementation.
- Rich ecosystem and comprehensive documentation.
- Well suited for data-intensive applications such as document management systems.

### Negative

- Larger bundle size compared to lightweight UI libraries.
- Customizing the default design may require additional configuration.
- Developers need to learn Ant Design's component APIs and design conventions.

### Risks

- Heavy reliance on Ant Design components may make migration to another UI library more time-consuming.
- Major version upgrades may introduce breaking changes requiring code updates.
