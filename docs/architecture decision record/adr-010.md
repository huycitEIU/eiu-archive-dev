# ADR: Use Archiver for Downloading Multiple Files as ZIP

## Status

Accepted

## Context

The document storage system stores uploaded files in Cloudflare R2 using an object key structure based on the document ID:

`<documentId>/<timestamp>-<filename>`

This allows all files belonging to the same document to be grouped by the document ID prefix.

The system needs to provide a **Download All** feature that allows users to download all files belonging to a document as a single ZIP file.

Downloading each file individually would require multiple requests from the client and would provide a less convenient user experience. Creating the ZIP entirely in memory would also consume a large amount of server memory when documents contain large files.

Therefore, the system needs a solution that can:

- Combine multiple files into a single ZIP archive.
- Stream files directly from Cloudflare R2.
- Avoid loading all files into server memory simultaneously.
- Stream the generated ZIP directly to the client.

## Decision

We will use **Archiver** to generate ZIP archives dynamically on the backend.

The backend will:

1. Retrieve all R2 objects whose key starts with the document ID prefix.
2. Retrieve each object from Cloudflare R2 as a readable stream.
3. Append each file stream to an Archiver ZIP archive.
4. Pipe the ZIP archive directly to the HTTP response.
5. Finalize the archive after all files have been appended.

The resulting flow is:

```text
Client
  │
  │ GET /documents/:id/download-all
  ▼
Backend
  │
  │ List objects with prefix <documentId>/
  ▼
Cloudflare R2
  │
  │ File streams
  ▼
Archiver
  │
  │ ZIP stream
  ▼
HTTP Response
  │
  ▼
Client downloads <documentId>.zip
```

A typical implementation is:

```ts
const archive = new ZipArchive({
  zlib: { level: 6 },
});

for (const object of objects) {
  if (!object.Key) continue;

  const body = await storageService.getFileStream(object.Key);

  if (!body) continue;

  const fileName = object.Key.split("/").pop();

  if (!fileName) continue;

  archive.append(body, {
    name: fileName,
  });
}

archive.pipe(res);
await archive.finalize();
```

## Consequences

### Positive

- Provides a convenient **Download All** feature through a single HTTP request.
- Supports streaming instead of loading all files into memory.
- Works naturally with the existing Cloudflare R2 object-key structure.
- Allows files to be retrieved and compressed dynamically without creating a temporary ZIP file in storage.
- Reduces the number of requests required from the frontend.

### Negative

- ZIP generation consumes backend CPU and network resources.
- Large documents may take a significant amount of time to generate.
- The backend must remain connected while the ZIP is being generated and downloaded.
- Additional error handling is required for failures during R2 streaming or ZIP generation.
- `ListObjectsV2` pagination must be handled if a document contains more objects than a single R2 listing response can return.

## Alternatives Considered

### Download Files Individually

Each file could be downloaded separately using its own presigned URL.

**Rejected because:** it requires multiple client requests and provides a worse user experience for downloading an entire document.

### Create ZIP in Memory

All files could be downloaded into memory, compressed, and then returned to the client.

**Rejected because:** memory consumption would increase significantly with large files or documents containing many files.

### Create and Store ZIP in R2

The backend could generate a ZIP file and store it in R2 before providing it to the user.

**Rejected because:** it introduces additional storage management, synchronization, and cleanup requirements for generated ZIP files.

### Use a Different ZIP Library

Other ZIP libraries could be used to generate the archive.

**Rejected because:** Archiver provides a suitable streaming API for Node.js and integrates naturally with the existing Node.js/Express backend.

## Result

Archiver is adopted as the ZIP generation library for the document **Download All** functionality. The implementation will use streaming from Cloudflare R2 through Archiver to the HTTP response to minimize backend memory usage.
